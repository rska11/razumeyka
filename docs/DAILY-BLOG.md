# Ежедневная статья для «Знайтона»

## Выбранный вариант

Использовать Codex с входом через ChatGPT, а не платный API генерации текста. Проверено локально: `codex login status` возвращает `Logged in using ChatGPT`. Работа расходует лимиты подписки; отсутствие API-платежей не означает отсутствие лимитов. Отдельные API OpenAI и Anthropic не использовать без новой команды владельца.

Настроено задание Windows Task Scheduler `Znayton-Daily-Blog`: основной запуск ежедневно в 09:00 по Москве, резервные в 09:30, 10:00, 10:30, 11:00, 12:00, 15:00 и 18:00, а также при входе пользователя в Windows. Запускается `scripts/run-daily-blog.ps1 -Run`, который вызывает Codex CLI через подписку ChatGPT. Компьютер должен быть включён, пользователь Windows должен быть залогинен; VS Code и приложение ChatGPT держать открытыми не требуется. При пропущенном времени включён StartWhenAvailable; для сна — WakeToRun (зависит от настроек питания Windows). При полном выключении выполнение невозможно. После подтверждённой публикации за день резервные запуски завершаются без обращения к GPT и без новой статьи. Число содержательных попыток Codex ограничено четырьмя за московскую дату; обрыв связи до начала работы не расходует этот лимит.

Исправление 9 ноября: запуск в 09:00 завершился в 09:03 с `workspace routing discovery failed` — не удалось соединиться с OpenAI. Настройка RestartOnFailure присутствовала, но повтор в 09:30 фактически не произошёл. Вместо неё установлены явные ежедневные триггеры. Проверка соединения через подписку в 09:50 успешна. Для smoke-теста теперь отдельный лог; журналы предыдущих попыток статьи сохраняются перед следующим запуском.

Отдельное задание `Znayton-Blog-Recrawl` каждый час вызывает `scripts/run-daily-blog.ps1 -RecrawlOnly`, без GPT и без подписки. Ошибки Вебмастера не препятствуют созданию и публикации статьи.

Исправление 8 ноября: запуск в 09:00 произошёл, но модель занялась только старой очередью переобхода и вернула skipped, что старый runner ошибочно считал успехом. Зависимость статьи от очереди удалена. Теперь skipped/failed дают ненулевой exit code и запускают повторы. Успех подтверждается по сегодняшней дате в локальных данных, заголовку и datePublished в JSON-LD живой страницы, sitemap и изображениям. Старая статья с HTTP 200 не закрывает новый день. Если сегодняшний коммит уже создан, но деплой не завершён, повтор продолжает его. Неизменённый черновик предыдущей попытки можно возобновить по сохранённым хешам; посторонние изменения по-прежнему блокируют автокоммит.

Для задания отдельно установлена CLI-версия `@openai/codex@0.167.0` в `.daily-blog/cli`; глобальная версия не изменялась. В CLI принудительно выбран провайдер `openai`, проверяется вход через ChatGPT и не передаётся OPENAI_API_KEY. Пробный запуск через подписку успешен; инструмент генерации изображений присутствует в окружении CLI. Полный цикл новой статьи будет проверен первым содержательным запуском; сегодня уже есть опубликованная статья, второй материал не создаётся.

Установка/обновление расписания: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-daily-blog-task.ps1`. Проверка доступа без генерации: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-daily-blog.ps1`. Проба подписки без действий: та же команда с `-SmokeTest`. Ручной рабочий запуск: с `-Run`. Отключение: `Disable-ScheduledTask -TaskName Znayton-Daily-Blog`.

Параллельные запуски исключены файловой блокировкой и настройкой IgnoreNew; завершение статьи отмечается по московской дате в `.daily-blog`. При незавершённых изменениях внутри school-next публикация пропускается. Логи, результаты и сообщения о сбоях — `.daily-blog`, исключена из Git. Токен — только `.env.blog`, также исключён из Git. Для ежедневной задачи не выводить ни один из файлов с секретами.

Документация OpenAI: https://learn.chatgpt.com/docs/scheduled-tasks и https://learn.chatgpt.com/docs/authentication.

## Яндекс Вебмастер

1. Войти в аккаунт Яндекса, которому принадлежит `https://znayton.ru` в Вебмастере.
2. Создать отдельное приложение: https://oauth.yandex.ru/client/new . В новом интерфейсе выбрать «Для доступа к API или отладки». Не менять приложение входа пользователей на сайт.
3. Заполнить название и контактную почту, добавить права `webmaster:hostinfo` и `webmaster:verify`. У этого типа приложения Redirect URI фиксированный: `https://oauth.yandex.ru/verification_code`, отдельно выбирать платформу не требуется. Актуальная инструкция формы: https://yandex.ru/dev/id/doc/ru/register-api .
4. Полученный ClientID подставить в `https://oauth.yandex.ru/authorize?response_type=token&client_id=CLIENT_ID` и открыть ссылку в своём браузере.
5. Токен вписать в `YANDEX_WEBMASTER_TOKEN=` в локальном `.env.blog`. Не пересылать в чат и не коммитить. Client Secret для этого потока не нужен.
6. Из `school-next` запустить `node scripts/yandex-recrawl.mjs --check`. Скрипт сам определит user_id и host_id; проверка ничего не ставит на переобход.

После публикации runner сохраняет URL командой `node scripts/yandex-recrawl.mjs --enqueue https://znayton.ru/blog/SLUG https://znayton.ru/blog` без вызова API. Прямая отправка вручную: `--submit` вместо `--enqueue`. При временных HTTP 429/5xx повторяются до трёх попыток; неуспешные URL сохраняются в `.daily-blog/pending-recrawl.json`. Повторить очередь: `node scripts/yandex-recrawl.mjs --retry-pending`. Это делает отдельное часовое задание, независимо от статьи.

Проверено 7 ноября: токен действителен, сайт подтверждён, квота 150/сутки (149 оставалось). POST переобхода возвращает HTTP 504 и с локального ПК, и с VPS. Это не подтверждённая отправка: статья о логике и `/blog` пока находятся в локальной очереди повторных попыток. Не заявлять, что Яндекс принял URL, пока API не вернул task_id или URL_ALREADY_ADDED.

Скрипт разрешает только HTTPS-адреса блога нашего домена, убирает дубли URL, понимает «уже добавлен», не печатает токен или тела ошибок API. Отправление в очередь не гарантирует индексацию. Согласно документации Яндекса, токен может потребовать обновления через 6 месяцев.

Официальные инструкции: https://yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth и https://yandex.ru/dev/webmaster/doc/ru/reference/host-recrawl-post .

## Ключевые запросы

Основной запрос желательно 2000–3000 показов, потолок 3000. Не придумывать частотность. Данные без подтверждённого периода и региона нельзя считать свежими.

Для старта можно подготовить очередь из свежего экспорта Wordstat. Для автоматического обновления нужен Wordstat API: https://yandex.ru/support2/wordstat/ru/content/api-wordstat . На 7 ноября 2026 официальная страница перенаправляет подключение API в Yandex Cloud / Search API. Это отдельный сервис с собственными доступами, ролью `search-api.webSearch.user` и условиями тарификации; его не подключать без согласования. Токен Вебмастера не даёт доступа к Cloud Wordstat API. Старые инструкции с `api.wordstat.yandex.net` не использовать без повторной проверки актуальности.

На старте разрешено опираться на реальные числа существующих выгрузок пользователя, как при последней ручной статье. В рабочих заметках обязательно указывать, что это сохранённые данные, а не текущий замер: период и регион не подтверждены. При появлении свежей выгрузки использовать её. Текущий потолок 3000 в реальном поиске без нового замера гарантировать нельзя. Если подходящих непокрытых ключей в таблицах нет, очередной запуск сообщает причину пропуска, а не выдумывает частотность и темы.

## Изображения

Сначала проверить на пробном задании, доступна ли встроенная генерация изображений в режиме расписания и укладывается ли она в лимиты подписки. Не считать наличие инструмента в текущем чате гарантией его наличия в CLI или задании по расписанию. Не переключаться автоматически на платный API. Если встроенная генерация недоступна, для статьи можно использовать подходящие собственные изображения проекта и авторские SVG-схемы; если они не подходят теме, оставить черновик и сообщить об ограничении.
